## A portfolio designed as a journey

The website brings my story and work into a cinematic desktop experience, with a dedicated mobile layout for comfortable reading on smaller screens.

- **Scroll-controlled storytelling:** a 300-frame image sequence rendered on canvas.
- **A cohesive visual stage:** portrait, animation and content share a scalable desktop composition.
- **Reversible motion:** content transitions follow scroll position in both directions.
- **A dedicated mobile experience:** a vertical layout suited to touch navigation.
- **Native browser interactions:** contact dialogs, FAQ accordions and keyboard focus states.

The site uses **HTML, CSS and JavaScript**, with no frontend framework or application server. GitHub Pages serves the public release.

## How I approach building

**Understand the purpose.** Start with the people, the problem and the experience the product should create.

**Make the structure clear.** Translate the idea into requirements, content, interfaces and manageable implementation steps.

**Care about the details.** Treat responsiveness, interactions and documentation as part of the product.

**Keep learning.** Be honest about what is complete, ask useful questions and improve through feedback.

## About this repository

This repository is the public showcase and deployment repository for my portfolio. The finished website lives in `site/`; GitHub Pages publishes that folder directly, with no build step here. Development source, planning, working notes and development history are maintained in a separate repository.

| Location | Purpose |
| :--- | :--- |
| `README.md` | Public profile, selected work and contact links |
| `site/` | Finished website, animation frames and CV |
| `.github/workflows/` | Publish the website to GitHub Pages |

Updates are prepared in the development repository, then the finished website files are copied into `site/` for publication.

The browser-delivered HTML, CSS, JavaScript and assets remain publicly readable. This separation keeps internal development work out of the public release while allowing visitors to experience the website.
